# DefencER 게임플레이 감사

- 작성일: 2026-09-01
- 상태: 개선 작업 전 기준선
- 범위: 현재 10라운드 프로토타입의 전투, 성장, 경제, UX, 안정성

## 1. 요약

현재 빌드는 시각적 정체성과 상태 머신의 기초 안정성은 좋지만, 핵심 선택인 **복제·합성·배치·카드 선택이 승리를 위해 서로 맞물리지 않는다.** 특히 합성은 대부분의 상황에서 총 전투력을 낮추고, 보스전은 단일 대상 딜러인 Rio 보유 수에 지나치게 좌우된다. 반대로 단순히 유닛을 계속 복제하는 정책은 200개 시드에서 모두 승리했다.

따라서 콘텐츠를 늘리기 전에 다음 순서로 시스템을 바로잡는 것이 우선이다.

1. 다중 시드 밸런스 하네스를 영구화한다.
2. 합성 곡선과 역할별 기여도를 재설계한다.
3. 웨이브 사이 준비 단계와 다음 웨이브 정보를 제공한다.
4. 행동을 바꾸는 카드와 보스 대응 선택지를 추가한다.
5. 전투 피드백, 기여도 통계, 온보딩을 보강한다.
6. 그 뒤에 40라운드, 신규 유닛, 메타 진행을 확장한다.

## 2. 감사 방법

### 2.1 직접 플레이

- 1920×1080 환경에서 시작부터 10라운드 보스 처치까지 플레이했다.
- 초기 배치, 복제, 합성, 카드 선택, 라운드 전환, 결과 화면을 확인했다.
- 1366×768, 1280×720, 1024×768에서 레이아웃 오버플로를 점검했다.
- 브라우저 콘솔 오류와 경고를 확인했다.

### 2.2 결정론적 시뮬레이션

진단용 임시 하네스로 아래 정책을 실행했다. 임시 파일은 감사 후 제거했으며, 결과만 이 문서에 남긴다.

- `initial-four-only`: 시작 시 네 번만 복제하고 이후 복제·합성·재배치하지 않는다. 5라운드에는 우선순위에 따라 제공된 카드 중 하나를 선택한다.
- `auto-spend`: 시작 네 유닛 이후에도 자금과 슬롯이 허용될 때마다 복제한다. 합성과 전략적 재배치는 하지 않는다.
- 분포 분석: `Math.imul(index + 1, 0x9e3779b9) >>> 0`으로 32비트 공간에 시드를 분산했다.

### 2.3 퍼즈 검증

128개 시드에서 시드당 최대 8,000회의 복제·이동·합성·폐기·스킵·카드·틱 액션을 섞어 실행했다. 다음 불변식을 검사했다.

- 유닛·적·투사체 ID 중복 없음
- 슬롯 중복과 잘못된 슬롯/성급 없음
- 재화·티켓·리롤 횟수 음수 없음
- `NaN`과 `Infinity` 없음
- 카운터 역행 없음
- 알림 큐가 5개를 초과하지 않음

분산된 1,024개 시드의 초기 4유닛 정책 결과다.

| 보유 수 | Rio | Leni | Adina | Hyunwoo |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 0% (346) | 44% (317) | 31% (338) | 20% |
| 1 | 11% (456) | 14% (464) | 19% (434) | 21% |
| 2 | 59% (175) | 1% (199) | 8% (207) | 18% |
| 3 | 100% (45) | 0% (41) | 0% (38) | 23% |
| 4 | 100% (2) | 0% (3) | 0% (7) | 0% (3) |

괄호는 표본 수다. Hyunwoo는 뚜렷한 상관이 없었고, Rio는 보유 수가 승률을 사실상 결정했다. 현재 보스가 단일 대상 화력 검사로 작동해 광역·지원 역할의 가치를 구조적으로 무효화한다.

## 4. 우선순위별 문제와 개선안

### P0-1. 합성이 총 전투력을 파괴한다

성급 배율은 [전투력 규칙](../src/game/domain/rules/stat-rules.ts)에서 `1.0 → 1.2 → 1.4 → 1.6 → 1.8`이며, 5성만 추가 1.3배를 받아 2.34가 된다. 동일 유닛 두 개를 합치면 슬롯 하나를 얻는 대신 총 기본 전투력이 다음처럼 감소한다.

| 합성 | 합성 전 | 합성 후 | 총량 변화 |
| --- | ---: | ---: | ---: |
| 1성 + 1성 → 2성 | 2.0 | 1.2 | -40% |
| 2성 + 2성 → 3성 | 2.4 | 1.4 | -41.7% |
| 3성 + 3성 → 4성 | 2.8 | 1.6 | -42.9% |
| 4성 + 4성 → 5성 | 3.2 | 2.34 | -26.9% |

지원 효과도 같은 문제가 있다. Leni의 1성 표식 두 개는 중첩 시 약 44%의 효과가 되지만, 합성한 2성 하나는 24%다. 합성은 슬롯 압박이 극심한 경우가 아니면 함정 선택이다.

**개선 방향**

- 합성 후 단일 유닛의 기대 기여도가 재료 둘의 85~110%가 되도록 성급 곡선을 다시 잡는다.
- 공격력만 키우지 말고 사거리, 타깃 수, 관통, 스킬 주기, 표식 유지 등 역할별 특성이 성급에 따라 변하게 한다.
- 높은 성급이 슬롯 효율과 행동 변화라는 명확한 보상을 주도록 한다.

**완료 기준**

- 자동 복제와 적절한 합성 정책의 승률 차이가 10%p 이내이고, 어느 한쪽이 모든 시드에서 우월하지 않다.
- 동일 자원 기준 합성이 즉시 30% 이상의 기여도 손실을 만들지 않는다.

### P0-2. 보스가 Rio 보유 수 검사다

Rio가 0명인 초기 조합은 346개 시드에서 한 번도 승리하지 못했고, 3명 이상이면 거의 항상 승리했다. Leni와 Adina는 보유 수가 늘수록 오히려 승률이 급락했다.

**개선 방향**

- 단일 보스 하나로 끝내지 말고 소환물, 방어막, 페이즈 전환, 약점 노출을 섞어 광역·지원·고타수 역할에도 임무를 준다.
- 웨이브에는 군집, 방어형, 빠른 적, 지원 교란형을 섞되 다음 웨이브의 핵심 태그를 미리 보여준다.
- 역할별 기대 피해·지원 기여도를 시뮬레이션에서 별도 집계한다.

**완료 기준**

- 각 역할 0명/1명/2명 보유군의 승률 격차가 초기 조합만으로 30%p 이상 벌어지지 않는다.
- 최소 두 가지 이상의 비-Rio 중심 빌드가 동일 난이도에서 완주 가능하다.

### P0-3. 경제와 난이도가 핵심 행동을 요구하지 않는다

합성·전략적 재배치 없이 돈이 생길 때마다 복제한 정책이 200개 시드에서 100% 승리했다. 반면 직접 플레이에서는 1,745 크레딧을 남기고도 완주했다. [경제 규칙](../src/game/domain/rules/economy-rules.ts)과 [라운드 해석](../src/game/simulation/round-resolution-system.ts)이 플레이어에게 의미 있는 지출 결정을 강제하지 못한다.

**개선 방향**

- 복제 가격 증가, 슬롯 압력, 제한된 리롤/폐기 비용을 함께 조정한다.
- 전투 후 받은 피해, 처리 시간, 누수에 따라 경제나 위협도가 달라지게 한다.
- 최소한 두 개의 경쟁 지출처를 만든다: 신규 유닛 확보와 기존 유닛 강화/변형.

**완료 기준**

- 단순 자동 소비 정책의 승률이 목표 난이도 구간을 벗어나지 않는다.
- 승리 런의 잔여 재화 분포와 미사용 재화 비율을 정기적으로 기록한다.

### P1-1. 웨이브 사이 준비 시간이 없다

[카드 명령](../src/game/application/commands/card-commands.ts)은 카드 선택 또는 아이템 장착 직후 6라운드 전투를 바로 시작한다. 실제 플레이에서도 적이 1초 이내에 나타나 카드 효과를 읽고 배치를 조정할 시간이 없었다.

**개선 방향**

- 모든 웨이브 사이에 명시적인 `PREPARE` 상태를 둔다.
- 다음 웨이브의 적 수, 태그, 추천 대응을 표시하고 사용자가 시작 버튼을 눌러 전투에 진입하게 한다.
- 준비 단계에서 복제·합성·배치·카드 확인이 가능해야 한다.

**완료 기준**

- 카드 선택 뒤 자동으로 전투가 시작되지 않는다.
- 키보드와 포인터 모두로 준비 완료를 명시할 수 있다.

### P1-2. 트랙을 돈다는 사실이 선택에 영향을 주지 않는다

현재 적은 트랙을 반복해서 돌 수 있지만 회차별 위협 증가나 안정성 손실이 없다. 따라서 사거리와 배치 위치가 처리 시간 외의 긴박한 결과로 연결되지 않는다.

**개선 방향**

- 적이 한 바퀴를 돌 때 위협도 증가, 기지 안정성 감소, 이동 속도 증가 중 하나를 적용한다.
- 내부/외부 배치의 장단점을 명확히 하고, 현재 웨이브에서 예상 커버 구간을 시각화한다.

**완료 기준**

- 같은 유닛 구성이라도 배치에 따라 누수·처리 시간·승률이 유의미하게 달라진다.

### P1-3. 카드가 숫자 보너스에 머문다

현재 카드 풀은 6장이고 한 번 선택하며, 다수 효과가 `+18`, `+20` 수준의 수치 증가다. 선택 화면 자체는 시각적으로 명료하지만 빌드의 행동 양식을 바꾸지는 못한다.

**개선 방향**

- 10라운드에서도 2~3회의 선택을 제공하고, 보스 전에 대응 카드를 고르게 한다.
- 관통/도탄, 동일 대상 연속 공격 가속, 표식 종료 시 광역 폭발, 내부 배치 사거리 변화, 합성 시 버프, 적 회차별 추가 피해처럼 규칙을 바꾸는 카드를 우선한다.
- [카드 기록 패널](../src/ui/panels/CardHistoryPanel.tsx)의 고정 문구 `다음 카드 선택 ROUND 05`를 실제 상태에서 계산한다.

**완료 기준**

- 카드별 선택률과 승률을 기록하며, 한 카드의 선택률이 70% 이상으로 고착되지 않는다.
- 서로 다른 카드가 최소 세 가지 구별 가능한 빌드를 만든다.

### P1-4. RNG에 대응할 수단이 부족하다

초기 네 유닛의 역할 분포가 승패를 크게 좌우하지만 플레이어에게 역할 보정이나 선택권이 없다.

**개선 방향**

- 초반 역할 보호, 선택형 소환, 천장, 유료 스킵 중 하나 이상을 도입한다.
- 완전한 통제보다 제한된 적응 수단을 제공해 RNG의 정체성은 유지한다.

**완료 기준**

- 특정 핵심 역할이 0명인 초기 조합도 대응 선택을 통해 완주 가능하다.
- 동일 시드 재도전에서 다른 의사결정이 다른 결과를 만들 수 있다.

### P1-5. 전투의 원인과 결과가 잘 보이지 않는다

적과 투사체가 작은 원형 DOM 요소와 얇은 체력 바로 표현돼 스킬 발동, 피격, 처치 원인을 읽기 어렵다.

**개선 방향**

- 역할별 투사체·스킬 색과 형태를 구분하고 명중·치명타·표식·사망 피드백을 보강한다.
- 결과 화면에 피해량, 지원 기여, 처치, 최대 위협도, 합성 횟수를 표시한다.
- 효과 강도를 낮출 수 있는 접근성 옵션을 전제로 애니메이션과 사운드를 추가한다.

**완료 기준**

- 플레이어가 결과 화면에서 패배 원인을 역할별 기여도로 설명할 수 있다.
- 주요 상태 효과가 색상 하나에만 의존하지 않는다.

### P1-6. 온보딩과 키보드 탐색이 부족하다

[배치 보드](../src/ui/battlefield/PlacementBoard.tsx)의 20개 셀이 모두 `tabIndex={0}`이라 키보드 사용자는 셀을 하나씩 탭으로 통과해야 한다. Enter/Space 배치는 가능하지만 방향키 이동과 로빙 포커스는 없다. 또한 복제·합성·배치의 목적을 설명하는 튜토리얼이 없다.

**개선 방향**

- 첫 런에 복제, 배치, 합성, 웨이브 준비를 한 단계씩 안내한다.
- 그리드에 로빙 포커스와 방향키 이동을 적용한다.
- [하단 액션 바](../src/ui/hud/BottomActionBar.tsx)의 복제 버튼은 자금 또는 슬롯 부족 시 실제로 비활성화하고 이유를 표시한다.

**완료 기준**

- 키보드만으로 모든 핵심 행동과 한 번의 완주가 가능하다.
- 신규 플레이어가 외부 설명 없이 첫 합성과 첫 웨이브 시작을 수행한다.

### P2. 제품 완성도 항목

- 실행 중 일시정지와 즉시 재시작을 제공한다.
- 장기적으로 20~35분짜리 전체 런을 목표로 한다면 라운드 경계 저장/재개를 제공한다.
- 결과에 시드, 피해량, 최대 위협도, 합성 수를 남기고 동일 시드 재시도를 지원한다.
- 1024px 폭을 지원하거나 최소 폭 1180/1280px을 명시한다.
- [시간 포맷](../src/ui/shared/format.ts)의 60초 표기 `00:60`을 `01:00`으로 정규화한다.

## 6. 구현 로드맵

### 단계 1: 측정 기반 만들기

- 결정론적 다중 시드 하네스는 `npm run test:balance`로 실행한다. 빠른 확인은 기본 4시드, 정식 측정은 `BALANCE_SEEDS=1000 npm run test:balance`처럼 표본 수를 지정한다.
- 정책별 승률, 평균 시간, 잔여 재화, 유닛 수, 역할별 기여도를 출력한다.
- 대표 고정 시드 세트를 회귀 테스트에 둔다.

### 단계 2: 핵심 루프 교정

- 합성 성급 곡선과 역할별 성장 효과를 조정한다.
- 보스와 웨이브 구성을 역할 카운터 기반으로 바꾼다.
- 경제를 재조정하고 단순 자동 소비 정책을 다시 측정한다.

### 단계 3: 의사결정 공간 만들기

- `PREPARE` 상태와 다음 웨이브 미리보기를 추가한다.
- 트랙 회차의 결과를 추가한다.
- 행동 변화 카드와 보스 대응 선택을 추가한다.
- 제한된 RNG 보정 수단을 도입한다.

### 단계 4: 전달력과 접근성 보강

- 전투 피드백과 역할별 기여도 화면을 추가한다.
- 첫 런 온보딩과 키보드 그리드 탐색을 구현한다.
- 일시정지, 재시작, 반응형 범위를 정리한다.

### 단계 5: 콘텐츠 확장

- 위 지표가 안정된 뒤 40라운드, 신규 유닛, 카드 풀, 메타 진행을 확장한다.

## 7. 지속 검증 기준

모든 밸런스 변경은 최소 다음 게이트를 통과해야 한다.

- 1,000개 이상의 분산 시드로 정책별 승률을 비교한다.
- 특정 유닛 0/1/2명 보유군의 승률을 함께 본다.
- 자동 복제, 합성 우선, 균형 빌드 등 최소 세 정책을 비교한다.
- 대표 시드를 실제 UI로 플레이해 시뮬레이션과 체감이 일치하는지 확인한다.
- 퍼즈 불변식, 전체 테스트, 프로덕션 빌드를 통과한다.
- 1280×720 이상에서 문서 오버플로가 없고, 지원 최소 폭 정책을 충족한다.

현재 기준선 검증 결과는 다음과 같다.

- `npm test`: 4개 파일, 57개 테스트 통과
- `npm run build`: TypeScript 및 Vite 빌드 통과
- `git diff --check`: 통과

## 8. 해석상의 한계

- 직접 플레이는 한 시드의 관찰이며 전체 분포를 대표하지 않는다.
- `initial-four-only`도 5라운드에 우선순위로 카드를 하나 선택하므로 완전 무조작 정책은 아니다.
- 작은 연속 정수 시드는 현재 xorshift 초기 출력에 편향이 있어 조합 발생률 분석에서 폐기했다. 본문의 1,024시드 분석은 32비트 공간에 분산한 시드만 사용했다.
- 시뮬레이션 숫자는 원인 진단을 위한 기준선이지 최종 밸런스 목표가 아니다.
- 퍼즈 통과는 게임이 재미있거나 균형 잡혔다는 뜻이 아니라, 검사한 상태 불변식이 유지됐다는 뜻이다.

## 9. 결론

DefencER는 이미 시각적 톤과 기술적 기반을 갖췄다. 다음 성과는 콘텐츠 양보다 **합성이 성장으로 느껴지고, 역할이 서로 다른 문제를 해결하며, 다음 위협을 보고 배치를 바꾸고, 그 선택의 결과를 읽을 수 있는가**에서 나온다. 이 네 가지가 검증되기 전에는 라운드와 유닛 수를 늘려도 현재의 조합 편향과 자동 소비 우세가 함께 커질 가능성이 높다.
